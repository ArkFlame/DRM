# ArkFlame DRM v0.6.5

One Java 8 client library + one Next.js application. Advisory-only telemetry and BuiltByBit entitlement observations. No remote shutdowns, automatic bans, or forced licensing dependency. Identifiable extended telemetry requires server-owner opt-in.

## Repository

```text
client/   Java 8 library, Maven pom.xml, optional Gradle build.gradle, source/tests
web/      One Next.js App Router app: dashboard + v1/v2 telemetry API + persistent services
          public/maven/ is generated Maven/Gradle repository content
          .env contains unique generated admin password/secret (not committed)
docs/     Protocol v1/v2, integration, security, deployment and website roadmap
dist/     Versioned client JAR and repository copy after build
scripts/  build.sh, start.sh, init-env.sh, publish-maven.py
previews/  Illustrative UI HTML fixtures, render helper and preview PNGs (synthetic data)
```

## Setup

```bash
./scripts/init-env.sh   # only if web/.env does not already exist; will NOT reset existing password
./scripts/build.sh      # auto-generates a missing npm lockfile; requires Maven, Node/npm, npm registry access on first build
./scripts/start.sh      # auto-builds if missing/stale; starts Next.js on 127.0.0.1:3000
```

**Admin login:** `https://drm.arkflame.com/login`. Recover your generated password with:

```bash
grep '^DRM_WEB_PASSWORD=' web/.env
```

`web/.env` is created once, chmod 600, and ignored by Git. **Never use a universal shared default password.** Use secrets generated by init-env.sh; rotate after exposure. Reset deliberately by changing `DRM_WEB_PASSWORD` and `DRM_WEB_SESSION_SECRET` in that file and restarting. Keep `DRM_HASH_KEY` stable, otherwise existing BuiltByBit nonce digests cannot be correlated.

`DRM_ADMIN_TOKEN` and `DRM_API_URL` are deleted; Next.js uses its private in-process services for admin reads/mutations. Browser does not receive secrets. Session is a signed, HttpOnly, SameSite=Strict cookie valid for eight hours; state-changing routes enforce same-origin checks against the configured public URL or the effective trusted ingress Host. One Node process owns JSON writes. No multi-process deployment or serverless scaling with this storage backend.

## Integrate from Maven/Gradle

Repository: `https://drm.arkflame.com/maven/`  
Coordinates: `com.arkflame:arkflame-drm-client:0.6.6`

**IMPORTANT:** The v0.6.5 offline-compiled JAR in `dist/` is provided for local evaluation. To publish v0.6.6 at `/maven/`, run `./scripts/build.sh` on a host with Maven and npm access. This produces the canonical Maven JAR and publishes it once; do not manually publish the offline JAR first. Public repository access requires deployment of the site. Read `docs/INTEGRATION.md` for copy-paste Maven/Gradle dependency and shade examples. The library must be bundled/relocated into your distributed Minecraft plugin; Maven/Gradle compile dependency alone does not ship it.

At plugin startup (exact `plugin.yml` name is used as product identity):

```java
ArkFlameDrm.start(this);
```

Default endpoint: `https://drm.arkflame.com/api/v1/check`. If v2 telemetry enabled, also `/api/v2/events`. Server owner can opt in to additional node/player/operator/plugin/machine telemetry (plugin inventory now includes JAR basename without filesystem path) through the existing `arkflame-drm/telemetry.properties` config.

## API & Data

`POST /api/v1/check`: installation and BuiltByBit nonce advisory report.  
`POST /api/v2/events`: session/player-delta and node telemetry.  
`GET /api/health`: readiness probe.  
`GET /maven/com/arkflame/arkflame-drm-client/maven-metadata.xml`: artifact metadata.  
The dashboard and all policy/review mutations are only reachable after password login. `BLOCK` remains a **label**, never a remote disable.

Backend data moves from old `backend/data/*` into `web/data/drm.json` and `web/data/graph.json` (copy while services are STOPPED). Old data schema 1/2 retained. Never run old backend and new Next.js simultaneously against same JSON data.

## Verification

If `web/package-lock.json` is missing, `build.sh` invokes `generate-lockfile.sh` automatically and then uses `npm ci`. Review and commit the generated lockfile after the first successful dependency resolution. Subsequent builds use that lockfile. `start.sh` runs the same build automatically if no completed standalone output for the current release exists. Existing `web/.env` and `web/data` are preserved. A failed build prevents startup, and no incomplete release is marked ready. Maven and npm registry access are still prerequisites, not automatically installed.

`./scripts/build.sh` must run Maven package, Java integration test mains, native Node tests, TypeScript check, Next.js production build, and copy the static public repo into Next standalone output. Only after every stage succeeds does it remove `client/target`.
